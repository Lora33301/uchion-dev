Задача: Реализовать тарифные ограничения
Контекст
В проекте Uchion реализована подписочная система. У пользователей есть поле subscriptionPlan в таблице users (значения: free, starter, teacher, expert). Подписки через Prodamus уже работают. Нужно добавить реальные ограничения функционала по тарифам.
Перед началом изучи: CLAUDE.md, shared/plans.ts (если есть), все файлы роутов в server/routes/, api/_lib/ai-models.ts, api/_lib/pdf.ts, фронтенд страницы презентаций и генерации.

Требования к реализации
Архитектура

Создать единый конфиг тарифов в shared слое — одно место для всех лимитов
Все проверки в роутах должны читать лимиты из этого конфига, а не хардкодить числа
Тариф пользователя берётся из user.subscriptionPlan
Если конфиг планов уже существует — расширить его, не создавать дублирующий

Безопасность

ВСЕ ограничения проверяются на БЭКЕНДЕ. Фронтенд только скрывает/блокирует UI, но не является защитой
При попытке обойти ограничение через API — возвращать 403 с понятным сообщением на русском (например «Презентации доступны начиная с тарифа Методист»)
Проверка слайдов: бэкенд должен валидировать что teacher не может отправить slideCount=24 даже если подменит запрос
Водяной знак добавляется на сервере при генерации PDF — клиент не может его убрать

Подсчёт дневных перегенераций

Нужен способ считать сколько перегенераций пользователь сделал за сегодня
Если в текущей схеме нет возможности отличить обычную генерацию от перегенерации — добавить способ
Счётчик сбрасывается в полночь (по московскому времени, это российский сервис)

Водяной знак

Только для free тарифа
Полупрозрачный текст «УчиОН» по диагонали
На каждой странице PDF
Не мешает чтению, но заметен
Добавляется в серверную генерацию PDF (Puppeteer). Клиентский fallback (pdf-lib) не трогать
При пересборке PDF (rebuild-pdf) тоже учитывать тариф

GET /api/auth/me

Расширить ответ: добавить объект с лимитами текущего тарифа и текущим usage (сколько листов/презентаций/папок уже создано, сколько перегенераций сегодня)
Фронтенд будет использовать эти данные для отображения и блокировки UI

Frontend

Где функция недоступна по тарифу — показывать не просто «нет доступа», а название тарифа с которого доступно, и кнопку/ссылку на страницу тарифов
Для перегенерации: показывать счётчик оставшихся (кроме безлимита у expert)
Для презентаций у teacher: показать только 12 слайдов, остальные опции визуально заблокированы с пояснением
На Dashboard: показать использование лимитов (листы X из Y, папки X из Y, и т.д.)

Совместимость

Не ломать существующую функциональность — всё что работает должно продолжить работать
Не менять логику подписок, webhook, оплат — это отдельная система
Не менять формат существующих API ответов — только расширять новыми полями
Существующие хардкодные лимиты (20 листов, 15 презентаций, папки) — заменить на значения из конфига тарифов

Что НЕ нужно делать

Не реализовывать «ранний доступ» — просто пометка в конфиге на будущее
Не добавлять DOCX экспорт, QR-тесты — это будущие фичи
Не менять логику выбора модели AI в ai-provider.ts — только в ai-models.ts
Не создавать новые таблицы в БД без крайней необходимости
